# 文献题录采集与清洗入库系统 —— 需求文档补充（评审第 5 项）

## 1. 操作流程总览

```text
定时调度 → 会话复用 → 入口落地 → 按天检索 → 导出落盘 → 清洗入库 → 对账告警
```

## 2. 采集子流程（WoS / Scopus 日增量）

| 步骤 | 操作 | 输入 | 输出 | 异常分支 |
|------|------|------|------|----------|
| 2.1 | schtasks 每日触发（WoS 07:00 / Scopus 07:20） | 任务计划 | 拉起采集进程 | 机器关机则次日 state 水位自动续跑 |
| 2.2 | 读取 state 文件 `last_done`，计算待采日期 = last_done+1 … 昨天 | scihuber_state.json / scopus_state.json | 待采日期列表 | state 缺失则从昨日单天起采 |
| 2.3 | 加载本地 cookie，校验是否仍为高级 VIP | scihuber_session.json | 会话有效/失效 | 失效转人工验证码登录（不自动登录），登录后回写 cookie |
| 2.4 | 同一账号单会话确认，关闭多余标签页 | 浏览器上下文 | 单一采集窗口 | 出现"只能一人在线"则抢占本窗口会话 |
| 2.5 | 依次尝试入口落地（Scopus: Kr1 5841 / mlkd 5460 / NCU 6112；WoS: 上大代理） | 入口地址 | 落地成功的检索页 | 全部入口失败记 FAIL_LAND，state 不推进，次日重跑 |
| 2.6 | 按天窗口检索：WoS 用出版日期，Scopus 用 `ORIG-LOAD-DATE AFT 前天 AND ORIG-LOAD-DATE BEF 后天` | 日期 | 命中总数 total | total=0 记空日停留，不循环重搜 |
| 2.7 | 超 5000 窗口走 ISSN 分桶拆分（187 桶×400 ISSN，互斥完备） | 大日期 total | 若干 ≤5000 的子查询 | 子查询仍超限则继续 doctype/年份/语种拆分 |
| 2.8 | 导出（WoS: xls 分批 1000；Scopus: 网关 JSON 分页）→ 解析 → JSONL 落盘 | 检索结果 | wos_YYYY-MM.jsonl / scopus_YYYY-MM.jsonl | 解析失败行记 problems 日志，不中断 |
| 2.9 | 写 state：last_done=当日，last_total/last_new=计数 | 计数 | 更新后的 state | 失败日 complete=false，last_done 不推进 |

## 3. 清洗子流程

| 步骤 | 操作 | 输入 | 输出 |
|------|------|------|------|
| 3.1 | 读 JSONL，按主键去重（WoS: ut_unique_wos_id；Scopus: eid） | 原始 JSONL | 去重后记录 |
| 3.2 | 字段对齐到建表口径（WoS 66 列 / Scopus 11 列），多余键忽略、缺失键置 NULL | 去重记录 | 对齐行 |
| 3.3 | 数值规范化：被引数/使用量/年份转 INT，日期截取 YYYY-MM-DD | 对齐行 | 规范行 |
| 3.4 | DOI 关联：以 doi 为键打通两库；缺失刊名卷期页的记录经 CrossRef/OpenAlex 回填 | 规范行 | 回填行 |
| 3.5 | 批量入库（WoS 500/批，Scopus 1000/批），`ON DUPLICATE KEY UPDATE` 幂等 | 回填行 | MySQL 表 |
| 3.6 | 对账：按天分组计数与 state 对比，差异>阈值告警 | 表计数 | 对账报告 |

## 4. 入库子流程

1. 执行 `wos_mysql.sql` / `scopus_mysql.sql` 建库建表（含主键与索引）。
2. 运行 `wos_to_mysql.py` / `scopus_to_mysql.py` 批量导入。
3. 校验：`SELECT COUNT(*)`、按天分组、主键无冲突、索引生效。
4. 重跑安全：重复导入只刷新被引数/使用量等易变字段，不产生重复行。

## 5. 自动化调度与告警

- schtasks 每日 07:00（WoS）/ 07:20（Scopus），进程结束即退出，不驻留。
- 日志落 `BOOKNOTE_DATA/logs`，state 即水位，失败不推进、次日自动续跑。
- 告警信号：FAIL_LAND、NO_SESSION、complete=false，见日志即人工介入。
